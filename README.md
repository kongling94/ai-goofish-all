# AI Goofish All

基于 AI Goofish Monitor 的统一闲鱼监控与数字商品管理项目。一个 Git 仓库、一个 Docker Compose 项目、一个 Vue/FastAPI 管理入口，内部复用固定版本卖家引擎。默认运行隔离演练，不连接真实闲鱼账号。

**当前版本 v0.3.1：数字商品首版集成，可离线演练闭环；真实闲鱼发布、回复、发货仍需部署后逐项验收。**

## 功能与边界

| 功能 | 首版实现 | 验证边界 |
| --- | --- | --- |
| 采集、AI 分析、价格监控 | 保留原监控端；全局单采集任务；验证码、登录失效、403/429立即暂停 | 相关自动化回归通过，未重新登录真实平台 |
| 自有商品发布 | 目录 → 发布素材 → 卖家引擎发布 → 记录真实商品 ID | HTTP 适配测试通过，未真实发布 |
| 自动回复 | 商品固定回复、兼容接口 AI 回复；可配置 DeepSeek | 复用卖家引擎，未做真实买家消息验收 |
| 数字商品交付 | 固定文本或库存卡密，真实商品 ID 关联发货规则 | SQLite 离线订单闭环和适配测试通过，未真实发货 |
| 成交后续售 | 已交付、原商品不在售、有库存才允许；复用卖家引擎规则 | 离线条件判断通过，平台条件检查未实测 |
| 结果未知恢复 | 发布未知时人工关联商品 ID；绑定未知时读取已有卡券/规则核对 | 不自动重发未知写请求 |
| 正式补货 | 首次绑定前可导入；绑定后由卖家引擎管理 | **首版统一入口拒绝绑定后的补货**，避免本地导入假成功 |

不包含任意商品上下架、实时改价、实物供应链/物流、搬运他人商品并自动销售。监控结果只能预填标题和来源 ID，自有商品图片、描述、库存及交付内容需自行填写。固定文本交付不会消耗卡密库存。

## 快速部署

需要 Docker Engine 与 Compose v2。当前仓库没有预构建镜像，从固定源码构建两个服务。

```bash
git clone https://github.com/kongling94/ai-goofish-all.git
cd ai-goofish-all
cp .env.example .env
```

编辑 `.env`，设置 `WEB_USERNAME`、强 `WEB_PASSWORD`，并分别填写非空且独立的 `SELLER_PASSWORD`、`SELLER_JWT_SECRET`、`SELLER_SERVICE_TOKEN`。这些值仅保存在本地，不要提交 Git。保留 `ALL_EXECUTION_MODE=preview`。

```bash
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 all-app seller-engine
```

访问 `http://NAS地址:8010`，使用 `.env` 的管理账号登录，在侧栏进入“数字商品工作台”。主入口端口由 `ALL_PORT` 控制；卖家端没有对宿主机开放端口。监控原有配置、账号管理仍在统一入口中。

数据保存在 `runtime/monitor`、`runtime/seller`、`runtime/state` 和日志目录；提示词使用 Docker 命名卷 `prompts`，首次从镜像初始化。预览与正式业务数据库分开存储。更新前备份 `runtime`、`.env` 和提示词卷；不要使用 `docker compose down -v` 删除持久数据。

### 离线演练

1. 创建商品，选择“库存卡密”，填写自有素材，导入两个**虚构演练码**。
2. 点击“演练发布”，确认发布记录为 `preview`、没有平台商品 ID。
3. 在“订单演练”提交已付款订单，应为 `delivered`；重复同一订单不再扣库存。待付款订单付款后可继续，缺货订单补货后可继续。
4. 演练发送结果未知时保留 `unknown`，重复事件不会再消耗库存；取消或退款中不发货。
5. 在“自动续售”取消“原商品仍在售”，已交付且仍有库存时返回 `eligible=true`、`published=false`。这只验证条件，不真实发布。

演练模式在卖家 `CookieManager` 创建前分流、卖家 API 只开放健康检查，并关闭监控调度和手动采集启动。不能向演练账号页导入真实 Cookie。

### 切换正式模式

先备份，再将 `.env` 的 `ALL_EXECUTION_MODE` 改为 `live`，执行 `docker compose up -d --build` 重建两个服务。模式不能在管理页面直接切换。正式模式会恢复该模式已有卖家会话和规则，请先核对持久数据。

导入本人卖家登录态 → 配置回复 → 创建商品及初始库存 → 发布并确认平台商品 ID → 绑定卡券和自动发货规则 → 验证一个真实订单 → 按需要启用有条件续售。出现验证码或登录异常需人工处理，集成版本禁用已接入的自动滑块验证入口，不包含账号轮换规避。

“暂停新动作”会阻止桥接派发并传到卖家端的持久续售闸门；已提交动作无法撤回，实时消息和订单处理可能继续。暂停请求失败时应检查两个服务，不能把错误提示当作暂停成功。发布或绑定结果未知时先核对已有结果，不重新发布商品。

发货绑定未知：在卖家端确认卡券及规则编号，在统一入口“发布记录”填写并核对。服务会读取验证卡券名称、规则商品 ID、卡券关联和启用状态。首版卖家高级库存/规则管理仍用原引擎页面，可在受控维护期间通过临时本机端口转发访问 8090；未提供统一入口的正式补货管理。不要将引擎管理端口直接公开到互联网。

### DeepSeek

“客服回复 → AI 回复”预填 `https://api.deepseek.com` 和 `deepseek-flash`，API Key 由用户在页面填写；默认不启用 AI 回复、不允许议价。参数依据 [DeepSeek 官方接口文档](https://api-docs.deepseek.com/quick_start/agent_integrations/)。监控分析与卖家 AI 回复的设置分别保存；监控分析可在系统设置中填写同类兼容接口。未使用用户 Key 发起付费验证。

## 开发验证

沿用 Python/pytest 与 Vue/Vite 工具。Python 3.11+、Node 22+；安装根 `requirements.txt` 与 pytest、pytest-asyncio。跨卖家续售测试另需其已有依赖 `loguru`。前端在 `web-ui` 执行 `npm ci`。

```bash
python -m pytest -m 'not live and not live_slow' -q
npm run build --prefix web-ui
```

本版记录：完整离线套件 149 项通过，3 项真实外部服务测试排除；Vue 类型检查和 Vite 生产构建通过；本地 FastAPI + 构建页面已验证演练发布、订单交付、重复事件、库存扣减和续售条件。新测试使用真实 SQLite，HTTP 适配测试只替代外部服务边界。**当前执行环境没有 Docker，未验证两容器构建启动；未连接真实闲鱼、未发布/发送真实消息/发货；没有替换 NAS 上原来的容器。**

架构与实施范围见 [设计](docs/superpowers/specs/2026-11-01-all-design.md)、[实施计划](docs/superpowers/plans/2026-11-01-digital-commerce.md)。上游来源与固定提交见 [THIRD_PARTY_NOTICES](THIRD_PARTY_NOTICES.md)，卖家定制点见 [vendor-changes](docs/vendor-changes.md)。整体分发按 AGPL-3.0 保留许可，原监控 MIT 许可保存在 `licenses/Usagi-MIT.txt`。
